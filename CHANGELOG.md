# Secure File Host changelog

## Unreleased

 * Repository, bugs and homepage links, the README badge and the tests workflow point at `buttercup-fork`. The workflow runs Node 20, 22 and 24 with current actions, and can be started by hand
 * `engines`: Node 20 or greater

 * **Security**: the host listened on all network interfaces; it now listens on the loopback addresses only
 * **Security**: requests with a `Host` that is not this machine, or an `Origin` that is not a browser extension, are rejected with `403` (stops DNS rebinding and web pages that send an `Origin`)
 * **Security**: requests a browser marks `Sec-Fetch-Mode: no-cors` (a web page's `fetch`, image or script request, which carries no `Origin`) and page-to-page navigations are rejected with `403`. Before this, a web page could make the host show a pairing code, or block pairing. Browser extensions (cors mode), other programs (no `Sec-Fetch` headers) and a visit typed in the address bar still work
 * **Bugfix**: the request body limit was the 100 KB default, so saving a file of about 75 KB or more failed with `413`. It is 25 MB now
 * Errors are answered as plain text (`400`, `413`, `500`) instead of an HTML page with a stack trace
 * Entering a connect code while no pairing is pending answers `400` without blocking pairing for 15 seconds, and no longer emits `connectionFailed`. A wrong code while a pairing is pending still does both. The connect code is compared in constant time
 * Dependency updates (`npm audit fix`): `express` 4.22, `body-parser` 1.20.8, `iocane` 4.2.1; the lockfile is now version 3. `iocane` still pins `pbkdf2` 3.0.17, whose advisories concern its JavaScript fallback; Node uses its native `crypto.pbkdf2` there (checked on Node 24)
 * **Security**: the generated cipher key and connect code use `crypto.randomInt` instead of `Math.random`. A key generated by an earlier version is still accepted when passed in, but should be regenerated
